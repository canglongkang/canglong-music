## 本轮改动

### 1. 新下载命名统一为「歌名 - 歌手.ext」

- `core/api.py` 的 `_safe_stem()` 改为 `title - artist` 顺序。
- **只影响全新下载**：补歌、联网重下、重搜替换仍沿用原文件名，老歌零改动。
- 读取端 `library.decide_order` 仍对两种顺序都兼容，不需要迁移存量。

### 2. 网格视图长歌名滚动越界

- 根因：`@keyframes ph-roll` 移动的是 `.gc-name` 整体，而父 `.grid-card` 没有 `overflow:hidden`，滚动时文字连同裁剪边界一起移出卡片、压到邻卡。
- 修复：`.grid-card` 加 `overflow:hidden`。代价是封面外扩的柔和阴影一并被裁掉（可接受）。
- 动画仍只在「正在播放」或桌面端 hover 时启动，符合原设计。

### 3. 右键 / 长按新增「编辑文件名…」

- 新增 `POST /api/songs/<id>/rename`：只改 basename、保留扩展名，库内 `NOCASE` 查重 + 磁盘重名自动加 `(2)`，同步 `db.move_paths()`。
- **刻意不写音频标签**：写标签会改 `file_hash`，目录对账会把它误判成「删除+新增」，连带歌词被 CASCADE 清掉。
- 修复：文件被媒体扫描/播放占用时，`os.replace` 抛 `ETXTBSY` 后原回退 `shutil.move` 会「复制成功、删源失败」，留下磁盘两份文件但数据库仍指旧路径的半成品。现在占用时直接友好提示并回滚；其他回退失败也会清理半成品副本。

### 4. 歌词写入音频文件本身

- 新增 `core/embedded_lyrics.py`，按格式分派：
  - MP3 → ID3 `USLT`（`encoding=3`）
  - M4A/MP4 → `©lyr`
  - FLAC/OGG/Opus → Vorbis comment `LYRICS` + `UNSYNCEDLYRICS`
- 写前备份到 `.lyrbak`，写后校验文件结构可解析，失败回滚。
- 抓取歌词、手动编辑、候选应用后自动写入；删除歌词（含批量清理）同步清除文件内嵌歌词。
- 数据库未命中歌词时回退读取文件内嵌标签，其他播放器写入的歌词也能识别（读回后顺手回填数据库）。
- 单一数据源仍是数据库，文件内嵌只是镜像；WAV/APE 跳过。
- PyInstaller spec 的 `hiddenimports` 补齐 mutagen 子模块。

### 5. 歌词重新搜索：预览 + 多结果选择

- `core/lyrics.py` 新增 `search_candidates()`（四源候选、每源 3 条、去重、按分数降序、上限 8）与 `candidate_lrc()`（LRC 惰性抓取，避免放大请求触发限流）。
- 新增三个接口：`POST /api/lyrics/<id>/search`、`/preview`、`/apply`，均不自动覆盖旧词。
- 前端新增 `#lyrPickModal` 候选面板：歌名/歌手查询 → 候选列表 → 点选预览 → 「应用这条」。
- 「重新搜索歌词」按钮改为打开此面板；手动编辑过的歌词不会被悄悄覆盖。
