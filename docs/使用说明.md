## 一、快速开始

1. 双击 `苍龙音乐管理播放器.exe`（首次启动会在同目录建 `data\library.db`）。
   旧名字 `音乐播放器.exe` 也保留了一份，指向同一套程序，原有快捷方式不会失效。
2. 点右上角 **导入文件夹**，选一个目录 → 在弹出菜单里选「导入到哪个播放列表」。
   扫描完会自动跳到该列表。
3. 左侧 `＋` 新建列表；右键列表可重命名 / 删除（**删列表不删文件**）。
4. 双击歌曲播放；选中多首后点 **加入列表…** 可一次加入多个列表。
5. 顶栏入口：**歌单下载**、**搜歌**、**补歌**、**歌单整理**、**导入文件夹**、**外观**、
   **UP 主搜歌**。手机/平板屏幕窄，这些按钮会自动收进右上角的 **⋮ 菜单**里。

> 打包版是 onedir（`exe` + `_internal\`），**不要只拷贝 exe**，两样必须在一起。

## 二、界面

- **左侧**：播放列表。`全部歌曲` 是全库视图，`回收站` 里是已删待清理的歌。
- **右侧**：`列表` / `歌词` 两种视图，记住上次的选择。
- **列表列**：`#` / 标题 / 歌手 / 专辑 / **来源** / 时长。
- **底部**：上一首、播放暂停、下一首、进度条（点击跳转）、音量、播放模式。
  中央按钮显示的是「点下去会做什么」：**正在播放时是双竖线暂停键，暂停时是三角播放键**。
- **顶栏左侧**：程序名 `苍龙音乐管理播放器` 与版本徽标（如 `v0.3.1`）。

### 来源列（0.2.4 起）

每行标出这份文件是从哪下的、什么音质：`酷狗 320k`、`酷我 无损`、`B站 314k`、
`QQ`、`网易云`、`咪咕`、`本地`。点一下弹出**来源详情**：

- 封面、来源站、站内 ID（B 站就是 BV 号）
- 当初那条结果的原标题（下载后改过名的，这里能看出原名）
- UP 主 / 歌手、专辑、视频时长与本地时长的差
- 播放 / 收藏 / 弹幕、发布日期、分区、标签、简介（B 站才有）
- 文件的实际格式、码率、体积、**存储位置（完整路径，可一键复制）**
- 提示标签：`视频音轨（不是平台音源）`、`名称含版本字样`、`旧记录`
- 底部：**换源（重搜替换）…** 直接跳到换源流程，**复制 ID** 方便去原站核对

下载 / 补歌 / 重搜替换 / 歌单下载四条路径都会把来源快照写进库里，离线也能看，
不依赖源站是否还在。0.2.4 之前下载的歌只有「来源 + 站内 ID」，会标成 `旧记录`。

## 三、播放

- `空格` 播放 / 暂停，`Ctrl+K` 聚焦搜索框，`Esc` 关闭最上层弹窗。
- 播放模式：顺序 → 列表循环 → 单曲循环 → 随机（点击切换，会记住）。
- 队列播放时遇到文件不在的歌会自动跳过，不会卡死；全都不在才报错。
- 音量、列表视图偏好都会记住。

## 四、歌词

- **自动下载**：开始播放时后台去找，找到就存进库里，之后**离线也能看**。
- 四个源轮着试：**酷狗 → QQ 音乐 → 网易云音乐 → LRCLIB**（都免费、无需注册）。
- 找不到会缓存「没找到」，6 小时内不重复请求；同名状态另有 5 分钟冷却。
- 支持手动编辑 / 自己贴歌词；歌词面板里可以查看当前用的是哪个源。
- 换掉一首歌的文件后会自动清掉旧歌词，按新版本重抓。
- 歌词清理面板：可以删「不在歌单里」的歌的歌词，只留还在用的。
- **搜不到？点右上角「重新搜索」可以改歌名**（0.6.5 起）：会弹出「歌名 / 歌手」两个框，
  歌名带 `【交响】…《我恨明月不照我》…【Hi-Res】` 这类装饰时会自动提取《》里的真歌名，
  歌手框建议留空（B 站视频的「歌手」常是 UP 主，反而干扰搜索）。**只改这次搜索用的词**，
  不会改掉库里的歌名、标签或文件名；直接点确定等同于原来的一键重搜。
  如果换了词还是没有，多半是歌词源里只有无时间轴的版本，可以用「编辑」自己贴词。

## 五、联网补歌

- 文件丢了的歌在列表里带 **`缺`** 标，顶栏 **补歌 (n)** 显示数量，点开勾选后一起补。
- 核对很严，宁可报「没找到」也不塞错版本：
  - **版本一票否决**：现场 / 演唱会 / 巡演 / 音乐节 / 榜中榜 / 跨年 / 春晚 / 不插电 /
    翻唱 / cover / DJ / remix / 伴奏 / 钢琴 / 童声 / 片段 / 铃声，只要目标是录音室原版，
    带这些标签的候选直接排除（括号里、`- Live` 尾巴、专辑名里都算）。
  - 歌手必须对得上；歌名相似度 + 歌手命中度打分。
  - 时长硬校验：明显偏短（截取版）或偏长（串烧 / 循环视频）直接弃。
- **B 站只是最后手段**：七个音乐源全部失败时才兜底一次，不再用码率和平台音源比高低。
- 选中多个源都能下时**实测码率**，留最好的那份；有无损存无损。
- 补歌失败的条目旁有 **「看候选」** 按钮，点开直接带歌名歌手搜索，自己挑一版下载。

### 联网重下（0.2.6 起）

只按**歌名 + 歌手**两个关键字重搜全部源（不带时长，避免库里被污染的时长把正确候选卡死），
取最高分候选与现有记录比分，**分数更高才替换**，旧文件先进系统回收站。
没有分数快照的旧记录会用下载记忆里挑过的那张卡实算基准分。

### 全歌单联网重下（0.2.9 起）

四个入口都能发起，且**先弹出补歌面板列出 N 首让你确认**再跑
（预勾「联网重下」，可再勾「B站优先」）：

| 入口 | 范围 |
| --- | --- |
| 侧栏歌单名右键 →「联网重下整个歌单…」 | 该歌单全部歌 |
| 「全部歌曲」右键 →「联网重下全部歌曲…」 | 全库 |
| 歌曲列表多选后右键 | 选中的歌 |
| 列表空白处右键 | 当前整表 |

计划由后端按歌单直接查库，右键指向的不是当前视图也不会漏歌；单首失败只记这一首，不炸整批。

### B站优先

勾上后，过了匹配门槛的 B 站候选加 0.15 分参与排序，相同匹配度时优先从 B 站下；
**门槛不放低**，匹配不上的 B 站视频不会因加权混进名单。
已有无损或 ≥280kbps 的文件不再额外下 B 站。

## 六、在线搜歌

- 顶栏 **搜歌** → 输入「歌名 歌手」→ 结果直接在面板里给你挑。
- 七个音乐源（酷狗 / QQ / 网易云 / 酷我 / 咪咕 / 千千 / 汽水）＋ **B 站**。
- **排序**：同名不同源自动合并成一条；B 站固定排最前，组内按相关度。
  标题 / 标签 / 简介里带 **4K / 2160P / Hi-Res / 无损 / 60 帧** 的再往前一点；
  带「现场 / 直拍 / 演唱会」的只按 20% 计，免得高清饭拍把原版挤下去。
- **每条能看到**：封面缩略图（加载失败退化成首字块）、歌名、`UP` 主、专辑、时长、来源；
  第二行是音质档（无损 / 320k 档）、播放量、收藏、弹幕、发布日期、分区、标签、简介。
  版本可疑的（现场 / 翻唱 / DJ）在歌名前打红徽章。
- 勾选后 **下载并加入列表**：选目标列表（含「全部歌曲」对应根目录），文件名
  `歌手 - 歌名.扩展名`，重名自动加 `(2)`，不覆盖。
- **你勾哪条就下哪条**，下不动直接报错，不会偷偷换一版别的回来。

### 按 UP 主搜歌（B 站，独立入口）

顶栏 **UP 主搜歌**（手机/平板在右上角 **⋮ 菜单**里）打开的是**单独一个面板**，
和上面的在线搜歌互不干扰：它不搜「某首歌」，而是把某个 UP 主的作品按**发布时间倒序**列出来。

- 输入 **UP 主名字**、**纯数字 mid**，或直接粘 **space.bilibili.com/…** 空间链接。
- 面板上方显示解析结果（名字 / mid / 粉丝 / 作品数 / 官方认证）。解析不准时点 **候选**
  换一个；像「周杰伦」这种正主没认证的，直接粘空间链接或 mid 最准。
- 列表显示视频标题、推断出的歌名/歌手（标题后面的小字）、时长、播放量、发布日期、简介。
  注意这里的「分数」全都是 1.0，只表示「是这个 UP 的作品」，**不是相关度**；
  分区、标签、收藏为空是 B 站作品列表接口没给，不是解析失败。
- 默认一次 30 条，点 **加载更多** 最多翻到 3 页（90 条）。B 站对这条链路限频较严，
  连点容易触发风控，所以搜索按钮在请求期间会禁用，**别连续猛点**。
- 目标列表下拉里选 **＋ 新建列表…** 会弹出输入框，填好名字确定后，下拉和左侧列表里
  立刻出现新列表（0.6.5 起）；按取消 / ESC 不会留下半截列表。
- 下载完成后，左侧各列表的歌曲数和「全部歌曲」总数会**立刻更新**；后台目录对账
  （每 10 分钟）改了库也会在半分钟内补刷，不用再等重开程序。
- 勾选 → 选目标列表 → **下载并加入**：和在线搜歌走同一套下载与进度显示，
  下回来的 `.m4a` 会写好歌名 / 歌手 / 封面标签。这条链路是 B 站直连，
  不依赖音乐引擎（引擎异常时也能下）。

> 入库的歌名沿用 B 站视频标题（与「在线搜歌里勾 B 站结果」一致），面板里的小字是
> 标题解析出的歌名，仅供参考；下载后想改名，在列表里右键重命名即可。

## 七、歌单下载与导出

### 下载

- 顶栏 **歌单下载** → 选清单文件 → 预览（序号 / 歌名 / 歌手 / 专辑 / 时长）→
  选目标列表与目录 → 逐首搜回、选优、入库入列。
- 支持酷狗 / QQ 导出的 `txt`、`csv`，以及 `m3u` / `m3u8`；无序号 txt 也认；
  自动识别 GB18030 编码；同曲去重；单次最多 500 首。
- 下载中可随时取消；失败的条目会写明原因（源返回 502、该源不可下载、时长不符…）。
- 面板里可勾 **「联网重下」**（清单里已在库的歌走重下规则，分数更高才换）与 **「B站优先」**。

### 导出（0.2.9 起）

侧栏歌单名 /「全部歌曲」/ 列表空白处 / 多选行右键 →「导出…」→
选 **TXT / CSV / M3U8** → 原生「另存为」→ 写出清单。
**只导出清单，不复制音频文件**；回收站不导出。

| 格式 | 内容 | 适用场景 |
| --- | --- | --- |
| **TXT** | `001. 歌名 - 歌手 [专辑] 3:45` | 可再用「歌单下载」原样导入回来 |
| **CSV** | UTF-8 BOM（Excel 直接开），含码率、格式、本地路径、来源、文件状态 | 盘点、核对曲库；文件状态按磁盘实查 |
| **M3U8** | `#EXTINF` + 本机绝对路径 | 给 VLC / foobar 用；换电脑后路径会失效 |

## 八、重搜替换与下载记忆

- 某首歌唱得不对：右键 → **这首不对？重搜替换…** → 在搜歌面板里挑一条 → 换掉文件。
- 换完会同步改：库里的歌名 / 歌手、文件内标签、文件名（保留 `006. ` 这种序号和原来的
  「歌名 - 歌手」顺序），歌词缓存也清掉。
- **记住你的选择**：挑过的那条记 `pick`，被换掉的记 `reject`。以后这首歌再丢，
  补歌优先按你挑过的那条找，也不会再下你已经否掉的版本。
- 记忆按「归一化歌名 | 归一化歌手」存，歌被彻底删掉再补回来时依然有效。

## 九、歌单整理（0.3.0）

按「主单」把音频文件实体重排到以歌单名命名的子目录。**只搬文件位置，不复制音频、不改歌单归属**：
曲库本来就是「一首歌一份文件 + 歌单纯引用」，所以其它歌单天然只保留引用，不会多占一份空间。

- **入口**：顶栏 **歌单整理**；侧栏歌单右键 **以此歌单为主单整理…**；
  「全部歌曲」右键 **歌单整理（全部歌曲为主单）…**。每次都要重新选主单。
- **根目录**：默认是程序所在目录下的 `Music`，每次都可以在弹层里点「更改…」换成任意目录。
- **归位规则**：
  - 主单里的歌 → `<根目录>\<主单名>\`；
  - 不在主单里的歌 → 按侧栏顺序取它所属的第一个歌单，进那个歌单的同名子目录；
    同时属于多个歌单的歌只落一个目录，其余歌单只引用；
  - 主单选 **全部歌曲** → 所有歌平铺到 `<根目录>\` 下，其它歌单全部只引用；
  - 缺文件的歌、回收站里的歌跳过；文件**不改名字、不改标签**，只换所在目录。
- **先预览再动手**：弹层列出每个目标目录放几首/多大体积、需移动数、同名改名数、
  缺文件跳过数、跨盘字节与目标盘剩余空间。目录名会去掉 Windows 非法字符，
  避开扫描器会跳过的名字；目标已有同名文件一律加 `(2)`，**绝不覆盖**。
- **搬文件**：同盘一次原子移动；跨盘先复制到临时文件、校验大小和内容指纹，
  再把原件送 **Windows 回收站**（还能找回）。单首失败只记这一首，不炸整批；
  可随时「停止整理」，已完成的会保留。完成后一次性批量更新曲库路径。
- **安全**：整理中补歌 / 下载 / 检查文件 / 导入文件夹会被暂时挡住，
  避免读到搬到一半的路径；执行前停播、结束后按新路径接着播；
  **撤销上次整理** 可把文件与曲库路径一起还原；万一中途程序被关掉，
  下次启动会按日志把已搬好的文件补写进曲库。日志在 `data\organize\last.json`。
- **注意**：
  - 整理不改变下载目录，之后新下的歌仍在原下载目录，下次整理再归位；
  - 歌单改名后磁盘目录不会自动跟着改，想按新名字归类就再整理一次；
  - 整理后若要重新导入文件夹，请选**新的根目录**，别再扫旧目录，
    否则会看到一堆「文件不在了」。
- **注意（0.6.0 起）**：启用「目录即歌单」后，歌单结构由磁盘目录决定，
  顶栏的 **歌单整理** 会自动隐藏；两套组织方式不要混用，见第十二章。

## 十、数据与文件

| 位置 | 内容 |
| --- | --- |
| `data\library.db` | SQLite 曲库：歌曲、列表、歌词、下载记忆、来源快照、设置 |
| `data\fetch.log` | 补歌、搜歌、替换、歌单下载日志 |
| `data\lyrics.log` | 歌词抓取日志 |
| `data\organize\last.json` | 上次歌单整理的执行与撤销日志 |
| `data\foldersync_cache.json` | 目录模式的增量扫描缓存（mtime+size）；删掉会自动重建 |
| `data\downloads\`、`data\dlwork\` | 下载与转码工作目录（可随时清空，程序会自动重建） |
| 音乐根目录 | 导入时选定的目录；整理后以用户选择的 Root 为准 |
| `<根>\_回收\<批次>\` | 目录模式下程序内删歌的回退区，按批次还原/清空（见第十二章） |

- 删除歌曲（旧模式）：文件进 **Windows 回收站**，还能找回；清空回收站才真正删除。
- 删除歌曲（目录模式）：文件**不进系统回收站**，而是搬到根目录下的 `_回收` 里，
  在「回收目录」面板可还原；只有在资源管理器里删文件才由系统回收站处理。
- 程序不联网上传任何东西；联网只用于歌词、搜歌、补歌、歌单下载。
- 升级/覆盖安装前建议备份 `data\library.db`（覆盖前后可比对 MD5 确认没被动过）。

## 十一、常见问题

**Windows Defender 报毒 / 文件被删**
PyInstaller 单文件风格的程序容易被误判。加排除项后重新解压即可；本程序不联网上传任何东西。

**某首歌显示「缺」**
文件被移动或删了。右键「联网补歌」就能找回；找到的路径会写回库里。
若刚做过歌单整理，请确认导入时选的是新的根目录。

**歌名 / 歌手不对**
右键「这首不对？重搜替换…」换一版；只改文件名的话程序会按文件内的标签校正，
手工改过的标题不会被覆盖。

**搜歌里 B 站结果很多，怎么判断**
看第二行的播放量 / 收藏 / 标签，和名字里的「现场 / 翻唱 / DJ」徽章；
来源详情里还有 UP 主和简介。拿不准就先用平台的条目。

**下载报 `502` / `song info unavailable` / `x509 certificate` 之类**
这类多属**平台风控或引擎证书链**问题，不是换源或升级引擎能根治的：
桌面端点顶栏「外观 → 引擎设置」打开引擎自带管理页，扫码登录对应平台、
配好 Cookie 再试；失败提示里现在也会带上这句引导。外观页还显示
**本次启动以来各源的成功 / 失败次数**（重启程序清零），方便看是全挂还是某一家。
安卓端没有引擎管理页；平台源大面积受限时，B 站结果是本程序直连下载的，
不经引擎，通常仍可用。

## 十二、目录即歌单

**0.6.3 起默认启用**（安卓 0.7.4 起）。一种按磁盘目录组织曲库的方式：
根目录树 = 左侧歌单树，1:1。

### 怎么开启 / 老库第一次升级

- **新装或空库**：进来就是目录模式，点顶栏 **设置根目录** 选目录即可。
- **已有旧平铺歌单的老库**：启动时会弹一次「切换到目录即歌单」，
  列出「检测到 N 个旧歌单、曲库 M 首歌」。点 **转为目录模式** 才切换，
  点 **暂时保留旧歌单** 就维持旧界面，以后随时点「设置根目录」也能切。
  之所以要问一句：转模式会**清空旧的平铺歌单**（只删列表、音乐文件一个都不动），
  而真机上可能有「我喜欢」这类攒了很久的歌单，不能替用户做决定。
  **0.6.4 起程序会自动兜底**：切换前先用 SQLite 在线备份把整份曲库
  复制成 `data\backup\<时间戳>-before-migrate.db`（只留最近 10 份），
  **备份不成功就直接取消切换**，不会先清了歌单再说。旧歌单结构想留底，
  从这份快照里还能查回来；音乐文件始终一个都不动。

选目录后预览显示「N 个目录 / M 首音频 / 将新建 K 个歌单」再确认。
安卓端会打开系统文件夹选择器（选完点「允许使用」）。

### 一条规则

- 一首歌只属于它**直接所在目录**的那个歌单；点父歌单只显示本级，
  徽标是「本级 / 含子孙合计」，不会一首歌出现在两个歌单里。
- 非音频文件忽略：不入库、不显示（删整目录时封面/歌词会跟着一起走）。
- **文件是真相**：在资源管理器里新建、改名、移动、删除文件，
  程序下次对账会跟着变；库只是磁盘的投影。

### 对歌单的操作 = 对文件的操作

| 你做的 | 磁盘上发生 |
| --- | --- |
| 新建子歌单 | 建一个目录 |
| 重命名歌单 | 目录改名 |
| 删除歌单 | 整个目录搬进 `_回收` |
| 把歌加到另一个歌单 | **移动文件**（不是复制、不是加引用） |
| 从歌单移除 / 删歌 | 音频文件搬进 `_回收` |
| 上移 / 下移歌单 | 不动文件，只改同级显示顺序 |

歌曲顺序按文件名自然排序（`01 / 02 / 10`），**不支持拖拽调序**；
目录顺序默认按目录名，可上移/下移。目录模式下顶栏 **歌单整理** 变成 **查重**。

### 查重（0.6.3 起）

点顶栏 **查重** → 按内容指纹（`file_hash`，入库时算好，不重新扫全盘）
列出重复组：每组显示「保留哪一份」和「哪些是多余副本」，默认全选。
确认后**多余副本按原相对路径搬进 `_回收/<批次-查重>/`**，在回收目录面板
可整批还原；文件不会被删除。保留规则是「目录层级最浅、同级按文件名自然序最前」。
没有内容指纹的老记录不参与判重（面板会报数），避免误判。
按钮要点两次才算执行，防止手滑。

### 回收目录

程序内删歌不直接删文件，而是搬到 `<根>\_回收\<批次>\<原相对路径>\`，
在 **回收目录** 面板按批次 **还原**（文件回原位后自动重新入库）或清空。
`_回收` 整棵跳过扫描，不会变成歌单。只有在操作系统里删文件，
才由系统回收站处理，程序只清记录。

**自动清理（0.6.2 起）**：面板顶部可开关与改天数，默认**开**、
保留 **30 天**内、并始终保底**最近 10 批**；超期批次在每轮对账后自动清理
（6 小时节流），还原/清空后剩下的空目录壳会立即收掉。
Windows 清理 = 送系统回收站（仍可找回）；**安卓没有系统回收站，
清理即永久删除、无法找回**，面板里也是这么写的。

### 换根与同步

再点「设置根目录」选新目录时会给三选：**移出曲库（文件留原地）/
一并搬进新根 / 取消**；新旧根目录不能互相包含。

同步时机：启动 4 秒后、每 10 分钟、手动 **立即同步**、还原之后；
程序自身的操作即时生效。安全兜底：根目录读不到（U 盘没插）时整轮跳过，
不会把曲库清空；一次性消失超过 20% 且超过 10 首会挂起，弹窗等你确认。

> **「缺失清单 → 联网补下载」已决定不做**：目录模式以磁盘文件为唯一真相，
> 在操作系统里删掉歌，下次对账直接清记录，库里不会再留下「有记录没文件」，
> 也就没有所谓「应有清单」可比对。需要留底请自行用「导出」保存清单。

**为什么有的歌只有 128kbps**
免费接口多数只给 128kbps mp3。有无损档的源会优先用；四个源都失败时才考虑 B 站音轨。
觉得版本不对可以用「联网重下」让它按歌名歌手重搜比一次分。

**点了导出，音频文件怎么没跟着走**
导出只写清单，不含音频文件，这是刻意设计（避免整库复制）。
需要连文件一起搬请用「歌单整理」，或手动复制 CSV 里列出的路径。
