## 0.6.4（安卓 0.7.5）— 正式发版

按拍板收口：**桌面真实库正式转目录模式**、真机受控写验证、双端发版。

① **迁移前自动备份**：新增 `core/backup.py`，用 SQLite 在线备份 API 生成单文件
一致性快照到 `data/backup/<时间戳>-before-migrate.db`（源库是 WAL 也不会拿到
半截快照，附属 `-shm` / `-wal` 随手清掉），只留最近 10 份。
`folders_migrate(convert)` 清普通歌单前先备份，**备份失败直接取消迁移**，
返回里带备份路径；迁移弹窗如实写明「切换前会自动备份」。
桌面真实 198 首库据此完成一次性迁移：5 个旧平铺歌单退役、5 个目录歌单、
对账「新增 0 / 清记录 0 / 更新 198」、音乐文件一个没动，快照已落盘。

② **风控失败引导 + 各源健康度**：`fetchsong.friendly_error()` 保留引擎原文，
只在 `song info unavailable` / Cookie / 酷狗 502 这类错误后追加一次
「外观 → 引擎设置扫码登录」；`GET /api/engine/health` 返回本次启动以来各源
成功/失败计数，外观页显示。**酷狗 / 咪咕 / 酷我的风控仍不是代码能根治的**，
这里只是把「下一步该做什么」写清楚。

③ **真机 #6 复测有结论**：真机 arm64 上三源搜索正常（30 条 / 0.3s / `warn=[]`），
但 netease / qq / migu 共 9 张卡下载**全失败** —— netease 报 VIP / 版权限制，
qq 报 `x509: certificate signed by unknown authority`（引擎取流 TLS 证书链），
migu 取流接口同样失败；同一轮 B 站对照下载成功（176kbps m4a），
说明播放器下载链路本身是通的。**「全源崩」不是 x86 模拟器特有**，
是平台源 / 引擎侧限制；要修得动 Go 引擎的证书池与 VIP 资源策略，本版不动。
测试文件按 `QA075*` 前缀精确删除并对账，曲库 1888 → 1887 零残留。

④ **真机查重闭环**：只读预览 8 组重复，挑 1 组（38MB flac）走完
「归集 → `_回收/<时间戳>-查重>` → 整批还原 → 对账」，
1887 → 1886 → 1887、文件回原路径、37 个歌单不变、回收批次清空、
logcat 无应用错误。顺带确认两端回收接口字段名都是 `items`（QA 脚本曾用错）。

⑤ **桌面 GUI 冒烟**：0.6.4 正式 exe 首次在真实 Windows 窗口跑完整流程
（迁移弹窗渲染 → 迁移后树形侧栏 `Music2 0/198` 与 4 个子目录、顶栏「查重」）。
截图在 `tools/qa_release_20261108/` 与 `android/docs/qa_075/`。

⑥ 回归：`qa_backup_health.py` 23 项、`check_copies.py --strict`、

## 0.6.3（安卓 0.7.4）

按拍板收敛长期双轨：**目录模式转为默认**，不再为新旧两套分支各写一遍功能。

① **转默认 + 存量库安全迁移**：`folder_mode` 改为三态（`'1'` 开 / `'0'` 用户选保留 /
`''` 未表态）。新装或空库直接落 `'1'`；检测到旧平铺歌单时**不静默清库**，
由 `bootstrap.folders.migration` 下发一次性确认面板，用户点「转为目录模式」
才 `drop_normal_playlists`（只删列表、音乐文件一个不动），点「暂时保留旧歌单」
则落 `'0'`。这条是给真机 1913 首 /「我喜欢」148 首这类真实数据的保护。
另加 `folder_root_set` 标记：新装默认开目录模式后，首次「设置根目录」
不会被误判成换根、误弹换根三选。
**边界加固**：真机 QA 发现「没有普通歌单但曲库已有一千多首」也可能是老库，
最初会被当成空库自动写 `'1'` 并触发自动对账；现改为只有
「无普通歌单 **且** 无歌曲」的真·空库才自动启用，其余一律弹确认。

⑤ 界面与回归：查重面板复选框被 `.modal-box input{width:100%}` 撑成整行、
把歌名挤成 0 宽，改用更高特异性选择器完整重置；顺手修了网格视图切歌时
`.c-no` 为空导致的 JS 报错（logcat 实测）。通知栏封面实测已生效
（Android 15 媒体卡片把 `ALBUM_ART` 铺成背景），另加本地首字方块占位图兜底。

② **查重复归集**（P2 #1）：新增 `core/dedup.py`，复用入库时的 `file_hash`
（`size + 首尾各 512KB sha1`）增量判重，**不重新扫全盘**；同组保留层级最浅、
同级自然序最前的一份，多余副本按原相对路径搬进

② **网格封面视图**：顶栏新增列表/网格切换。偏好存 settings 表
（**不用 localStorage** —— 安卓端口递增会让 origin 变、localStorage 丢失）。

③ **外观页升级**：字号四档（0.9/1/1.1/1.2）、播放页背景开关、迷你播放条开关。

④ **后端新增只读接口** `GET /api/player/queue`，给播放页队列面板用。

⑤ **修网格卡片塌陷**（严重，MuMu WebView）：网格卡复用列表 `.row`（为兼容多选），
`.row{height:42px}` 会把卡片压扁；更关键的是该 WebView **不把
`aspect-ratio`/`padding-top` 的内在高度计入 grid 父级行高**，导致卡片恒为 50px、
封面溢出重叠、文字被 flex-shrink 压成 0（完全不可见）。
`align-self:start`、`display:block`、绝对定位 img、flex-wrap 等纯 CSS 方案全部无效，
最终改为 **JS 显式尺寸**：封面高度 = 实测 `clientWidth`（正方形），
卡片高度 = 封面高 + 64px。显式高度能被 grid 行高正确采纳。

⑥ **修网格列数因内核而异**（真机复核发现）：原先用
`repeat(auto-fill, minmax(150px,1fr))`，轨道数是「按实际可用宽度再分配」，
不同 Chromium 版本算出的列数不一致 —— 真机 Android16 的 Chromium 在 360px 宽
只排 1 列，MuMu 的旧内核却排出 2 列 147px（低于 minmax 的 150px 下限）。
同一份代码在两种机器上布局不同，属于不可控。改为**按断点写死列数**
（手机 2 / 平板 4 / 宽屏 6 / 超宽 8），任何内核结果一致。
同时把 `1fr` 换成 `minmax(0,1fr)`：grid 轨道默认最小尺寸是 auto（= 内容 min-content），
而歌名是 nowrap 长标题，会把轨道撑到超出容器。

⑦ **修播放页顶部一条莫名横线**（真机复核发现）：`.np-info{max-width:92vw}`，
但 `vw` 是视口宽（360px），而 `.np-body` 内容区只有 320px（视口减去内边距）。
92vw=331 > 320 会让 `.np-info` 撑出容器，`.np-body` 的 `overflow-y:auto`
连带把 `overflow-x` 也算成 `auto`，于是在播放页渲染出一条**横向滚动条**。
改用 `max-width:100%` 并给 `.np-body` 加 `overflow-x:hidden` 兜底。

⑧ **版本号不再各写一份**：安卓端原先 APK 标 `0.6.1-p6`、界面却显示 `v0.4.2`
（读的是后端 `core/meta.py`），两处各写一份必然会漂移。现在安卓端在启动时
由 Kotlin 从 APK 的 `versionName` 读出真实版本号，经 `android_boot` 传给
`core.meta.set_version()` 覆盖，**安装包版本与界面显示版本永远是同一个数**。
桌面端 `core/meta.py` 保持唯一来源。

### 安卓版本号说明

桌面与安卓是两条独立的发版线，版本号不要求同步：
